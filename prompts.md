## Not committed yet: tamper-evident evidence and slow-network mode

**Goal:** add five verifiable features for the jury review while keeping the original flow (URL → scan → finding → repair prompt → retest) working in both the web app and the CLI.

**Combined prompt**

1. **Tamper-evident evidence.** Save every check result in an append-only log. Each record contains the hash of the previous record, so editing any past result breaks the chain. The database alone must not serve as proof of integrity.
2. **Offline verification.** An `npx vibeproof verify` command checks a report's hash chain without the server and identifies exactly which record was tampered with.
3. **Linked retests.** A retest shows "Fix Verified" only if it links back to the original run's hash and executes the same test.
4. **Slow network mode.** Route every browser request to the target site through a proxy built into the runner. The proxy adds delays and can duplicate requests to simulate slow networks.
5. **New bug detection.** In slow-network mode, detect a duplicate-account bug caused by a slow signup that a normal scan misses, and generate a repair prompt for it.

The jury holds a copy of this brief and will verify the implementation live. Meeting the requirements earns bonus points and missing them costs points. The brief was given twice, the second time after the source had been updated, with the instruction to redo the work.

**Follow-up tasks**

- Apply the database migrations: first the reset, then the schema (twice, once per redo). This included installing `psql`.
- Ask what remains to be done after each step.
